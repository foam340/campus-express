## 1. 本地开发与发布

| 端 | 源码 | 生产构建及输出 |
|---|---|---|
| 微信小程序 | `app.*`、`pages/`、`packages/`、`config/` | `npm run build:prod` → `dist/production` |
| Web 管理台 | `admin-web/` | `npm run build:admin:prod` → `dist/admin-web/production` |
| Node/Express + MySQL | `server/src/`、`server/sql/` | 后端独立发布，检查版本、实际进程路径及健康接口 |

安装依赖用 `npm ci`、`npm --prefix server ci`；全量检查用 `npm run check`。管理台本地可用 `npm run admin:dev` 和 Mock，生产包排除 Mock。后端从 `server/.env.example` 配置目标环境。小程序 AppID 和合法域名也须匹配目标环境。

从 main 开分支，按范围检查后推送并提 PR。保留已有图片及无关工作，凭据、生产访问参数、个人数据、备份、日志、工具和构建产物不入仓库。静态站只部署实际变化的构建文件，备份放在 Web 根目录外；发布后核对公网文件。后端上线需要基线、备份、语法、进程路径及实际查询验证；健康接口通过不代表业务验证通过。

历史迁移和数据清理不重跑。涉及数据库写入时，先核验对象及授权，备份、加前置断言、事务、审计及回读。新增表同步维护 schema、迁移及重置清单。数据库时间用 UTC，北京自然日统计单独转换；保留已有客户和订单。

## 2. 多校区、价格与订单

- 前端 `config/constants.js`、后端 `server/src/campus-config.js` 及管理台配置保持一致。南海 9 栋和教师公寓 A/B 座豁免同性接单限制；石牌用楼栋白名单与自由房号，送上楼限本栋；广轻工 1–48 栋及东1/东2，9–24 栋女，其余男，东1兼容旧键「东一」。
- 南海小/中/大件校内外为 1/2、3/4、5/6 元，9 栋固定加 0.5 元，门口费另计。广轻工东1/东2每单距离费 0.5 元，门口 1–3 楼 0.5 元、4 楼及以上 1 元，楼下无门口费。抽成南海/石牌/广轻工为 10%/10%/20%。各校区独立读费率，历史订单按快照，不重算。
- V3 全部附加费参与满减，默认满 5 减 0.5、满 10 减 1、满 20 减 3，只取最高档再抵券；V2 保留仅件小计口径。服务端按协议以整数分核对报价；`toDoor` 与 `noUpstairs` 语义相反。
- 首页文案 08:00–20:00，后端建单 07:30–20:00。普通模式今天 23:00 前，稍急/很急为下单后 4h/1h、整单 +2/+4；晚间稍急不截短。稍急仅 V3，审核保持原两档，支付、接单和转单不重置时限。
- 大厅展示本校区已支付的待接单订单；大厅与接单共用服务端 `evaluateOrderGrab`。只有 accepted 可转单，2h 内不能接回，每天最多 3 次。送达至少一张凭证，送达后固定 12h 自动完成，观察期独立默认 24h。
- XorPay 为原生扫码；零元券单取消只退券，`manual_review` 退款不自动补退。订单净收入排除未支付和取消单，扣除实际计入的骑手收入；券损由平台承担。额外收支加到「实际净收入」及今日卡片，保留纯订单口径的折线与明细。

## 3. 注册、转校区及审核模式

- 正常注册选择校区后核对楼栋；未选时弹列表并保留输入。姓名备注、真实姓名、昵称及用户/骑手手机号是独立字段。
- `POST /mini/campus-change-requests` 校验通过即时生效。用户须无未结束订单，骑手还须无未结束配送任务；有售后且均已结案的 disputed 可视为结束，订单和账目状态不变。事务同步 users/riders、待审骑手申请并清旧地址，留请求历史；人工转区审核接口已移除。
- 优惠券按校区过滤，NULL 为通用；转区不迁旧券。按手机号定向发券仍存在多账号歧义，不能以相同号码推定为同一人。
- `review_mode` 是全平台开关，保留审核文字、操作和金额保护。独立设置决定模式；热刷新失败保留已确认值，冷启动未知保护金额。不得为验证临时切换生产值。新源码补了审核自动登记默认 campus；旧包仍可能报 INVALID_CAMPUS。
- 截图失败在正常模式可重试，先重新取详情核验权限，保留成功缓存和未上传凭证；权限失效时清理已失权数据。审核模式没有新增重试入口。改列表卡片行高时同步 recycle-view itemSize。

## 4. 管理台审核与提现

- 骑手「待审核申请」仅显示待处理记录。11 月 9 日改动只涉及 `admin-web/src/app.js` 的该表，服务端仍保留规则版本及审核记录。订单和骑手搜索保留既有校区、权限和过滤口径。
- 提现「操作」仅对待审核项显示「通过／驳回」，已打款或已驳回显示「-」。**实际转账后再点通过**：平台标为已打款、扣减可提现余额并记审计，不自动转账。驳回要填原因，不改变余额。
- 新申请的负责人提醒及通过后的骑手结清邮件是两类异步通知，失败不自动补发，邮件不代表到账。生产未为本次检查创建真实提现或修改资金记录。
